CHAPTER 01

「画像を分割する」とは限らない

Unit01では、画像を数値の配列として扱い、3×3のKernelがその一部分を参照して出力値を作ることを見ました。Unit02では「そのKernelをどのくらい移動させるか」と「深い層では入力のどこを参照できるか」を理解します。

畳み込みは、画像を独立したタイルに切り分ける操作とは違います。例えばStride 1で3×3 Kernelを動かすと、隣の出力位置が参照する領域は大きく重なります。

「特徴マップの1マス」は画像の1枚の小さな切り抜きではありません。複数チャネルの数値を持つ、計算結果の1つの空間位置です。

CHAPTER 02

Strideは出力位置の間隔

1次元の入力サイズを n、Kernelの大きさを k、両側のPaddingを p、Strideを s とすると、Dilation=1の畳み込みの出力サイズは次の式です。

out = floor((n + 2p − k) / s) + 1

今回の演習では、入力16×16、k=3、p=1で固定しています。

Stride出力サイズ出力位置の数
116×16256
28×864
44×416

Strideを2倍にすると、この条件では縦横の位置数がそれぞれ半分になります。ただし「参照する画素が重ならなくなる」とは限りません。Kernel=3、Stride=2でも隣の入力領域は1列重なります。

計算位置とPaddingの関係

出力位置 (oy,ox) のKernel左上が参照する入力座標は (oy*s−p, ox*s−p) です。左上が負になる場合は、範囲外を0として計算します。これは今回の zero padding の設定によるものです。

for oy in range(out_h): for ox in range(out_w): total = 0.0 for ky in range(3): for kx in range(3): iy = oy * stride + ky - padding ix = ox * stride + kx - padding if 0 <= iy < height and 0 <= ix < width: total += img[iy, ix] * kernel[ky, kx] out[oy, ox] = total
厳密には、PyTorchの Conv2d は数学的なKernel反転を伴う「畳み込み」ではなく、通常は相互相関として実装されています。この教材でもKernelを反転させずに積和を計算します。

CHAPTER 03

受容野は「1マスが参照し得る範囲」

出力のある1点が、入力画像のどの場所の情報によって変化し得るか。その入力領域を受容野（receptive field）といいます。Strideが8であっても、受容野の大きさが8×8であるとは限りません。

重ねた通常の畳み込み（Dilation=1）を考えると、受容野サイズ R と隣接する出力点の入力上の間隔 J は次のように更新できます。

R₀ = 1, J₀ = 1
Rᵢ = Rᵢ₋₁ + (kᵢ − 1) × Jᵢ₋₁
Jᵢ = Jᵢ₋₁ × sᵢ

例えば3×3、Stride 2、Padding 1の層を3回重ねた場合：

層出力サイズ累積Stride J理論受容野 R
入力1611
Conv 1823
Conv 2447
Conv 32815

結論：隣接位置の間隔は8マスですが、出力1点が参照し得る範囲は15×15マスです。

ここで扱うのは簡略化した直列3層CNNの理論受容野です。実際のYOLOXのBackboneやPAFPNは分岐・結合を持つため、ここでの15をYOLOXのP3の受容野にそのまま当てはめることはできません。また実際の勾配が強く集中する領域（実効受容野）とも区別します。

CHAPTER 04

YOLOXのP3・P4・P5は何を意味するか

標準的なYOLOXでは、特徴マップを複数の解像度で使います。一般的にP3/P4/P5の累積Strideは8/16/32です。入力が416×416なら次の位置数になります。

レベルStride空間サイズ検出候補位置数
P3852×522,704
P41626×26676
P53213×13169
合計3,549

重要なのは、これらが単純な「画像分割」ではないことです。各位置には特徴チャネルがあり、その特徴は多段の畳み込みと特徴統合から生まれます。特徴マップの空間位置と理論受容野は異なる概念です。

このUnitでは、P3/P4/P5の「位置を置く規則」とBBoxの「デコード」を再現します。実モデルの特徴テンソルを作成・表示するものではありません。

CHAPTER 05

格子原点・格子中心・予測中心を分ける

列番号を gₓ、行番号を gᵧ、Strideを s とします。YOLOXのHeadによるBBox中心のデコードに使う格子原点と、SimOTAの幾何的な候補判定に用いられる格子中心は異なります。

格子原点 O = (gₓs, gᵧs)
格子中心 A = ((gₓ+0.5)s, (gᵧ+0.5)s)

P3で s=8、(gₓ,gᵧ)=(22,12) の場合、原点は (176,96)、格子中心は (180,100) です。

これらは座標の取り決めです。CNNの畳み込みに由来する厳密な受容野中心と必ず一致するわけではありません。

CHAPTER 06

YOLOXは格子より大きなBBoxも出せる

Headが出す4つのraw値を (tₓ,tᵧ,t𝑤,tₕ) とすると、通常のYOLOXのBBox中心と幅高さは次のようにデコードされます。

cₓ = (gₓ + tₓ) × s
cᵧ = (gᵧ + tᵧ) × s
w = exp(t𝑤) × s
h = exp(tₕ) × s

先ほどのP3格子 (22,12) で、(tₓ,tᵧ)=(0.75,0.25) なら、予測中心は (182,98) です。一方 t𝑤 = ln(4/8) ≈ −0.693 とすれば幅は4pxになります。

ここで注意すべきは、tₓ,tᵧ は標準YOLOXではセル内に制限するsigmoid処理を介さずに使われることです。したがってBBoxの中心は、基準点がある8×8領域の外にも出せます。また指数関数で幅を決めるため、1つの格子位置から幅128pxのBBoxを表現することも可能です。

「格子の間隔が8pxだから、8px未満の物体を検出できない／8pxより大きいBBoxを出せない」は誤解です。ただし、小さい物体の識別情報が特徴マップで失われたり、IoUによる学習が難しくなったりすることはあります。

CHAPTER 07

SimOTAの幾何候補はBBox内に限られない

「GTのBBox内に格子中心が1つもない」という状況でも、幾何的な割当候補がまったく存在しないとは限りません。公式YOLOXのHeadにある幾何候補の中心領域は、GT中心から各軸へ 1.5×stride の範囲で定義されます。

|aₓ − GTₓ| < 1.5 × s
|aᵧ − GTᵧ| < 1.5 × s

仮想GTを中心 (184,101)、幅高さ 4×4px とした教材の例では、P3/P4/P5すべての格子中心を数えてもBBox内に格子中心はありません。一方、中心領域内の幾何候補はP3で6、P4で9、P5で9、合計24位置になります。

ここでいう24は幾何候補の数です。実際のSimOTAはさらに分類コストや予測IoUを使い、Dynamic Kなどにより最終正例を選びます。この教材はその最終割当を計算していません。

CHAPTER 08

極小頭部の問題から、BBox表現を発明する

4pxの頭部を予測できる数式を持っていても、実際に良い候補が出るとは限りません。原因は特徴抽出、割当、BBox回帰、スコアなどに分かれます。まずはBBox回帰の数式だけに焦点を当てることが研究の入り口です。

  1. 中心＋幅高さではなく、四辺を4つの値で予測すると何が変わるか。
  2. 基準点がBBox外にあっても四辺までの距離を表現するには、どのような符号が必要か。
  3. 左右・上下の境界が逆転した場合、どんな数式的・学習上の問題が起こるか。
  4. 極小BBoxを良くしても、大きなBBoxを学習しにくくなる可能性はないか。

答えをすぐ見る前に、まず自分で4出力からBBoxを生成する関数を1つ考案してください。この研究課題を発展させたものが、後続ユニットで扱うSigned LTRBです。
