00 / OVERVIEW

推論と学習は、どこから分かれる？

YOLOX-NanoのDecoupled HeadはP3/P4/P5の各格子についてBBox用raw値4つ、Objectness用logit1つ、クラスlogitを出します。80クラスなら格子あたり85値。416×416入力のP3(52²)、P4(26²)、P5(13²)を合わせて3,549位置です。

画像 → Backbone → PAFPN → Head raw ├→【推論】BBox Decode → Score → NMS → 最終検出 └→【学習】GTとの幾何候補 → SimOTA → IoU/BCE Loss → 微分・更新

この2つを混同すると「NMSで学習の正例を決める」などの誤解を招きます。NMSは基本的に推論後の重複削除、SimOTAは学習の正例割当です。

公開データの区別：Unit 04のStep 01は未学習・固定seedの実PyTorch rawを使用します。GTと学習候補を使うStep 02〜04は完全な架空の教材用例です。実写真の頭部GT、学習結果、認識性能を示すものではありません。
01 / BBOX DECODE

「grid番号」はBBox中心の画素ではない

Headは各格子の4値 (tx,ty,tw,th) を出力します。格子番号 (gx,gy) とstride s を使ってBBoxを復元します。

cx = (gx + tx) × s cy = (gy + ty) × s w = exp(tw) × s h = exp(th) × s x1 = cx − w/2 y1 = cy − h/2 x2 = cx + w/2 y2 = cy + h/2

例えばP3（s=8）の格子(3,5)でraw=(0.25, −0.5, ln2, ln3)なら、BBox中心(26,36)、幅16、高さ24pxです。tw,thに指数を使うため、正の幅・高さが保証される一方、対数値の変動が面積に大きく影響します。

重要な区別：デコード式は gx+tx です。一方、SimOTAの候補位置を判定する格子中心は (gx+0.5)×s です。+0.5 をDecodeへ勝手に足してはいけません。

Objectness・Classificationはlogitから計算

p_obj = sigmoid(z_obj) p_cls[k] = sigmoid(z_cls[k]) score[k] = p_obj × p_cls[k]

上式は計算上のスコアです。特に未学習モデルのscoreを「画像にその物体が写る確率」と解釈してはいけません。Unit 04では実rawを変更した瞬間に「仮想編集」へ表示が変わります。

02 / IOU & NMS

IoUは、位置が正しいかを測る幾何的な値

intersection = max(0,min(x2A,x2B)−max(x1A,x1B)) × max(0,min(y2A,y2B)−max(y1A,y1B)) union = areaA + areaB − intersection IoU = intersection / union

4×4pxのBBoxを横に1pxずらすと、共通面積12、和集合20となりIoUは0.6です。同じ1pxズレでも80×80pxの場合、共通面積6320、和集合6480、IoU≒0.9753になります。

一辺1pxずらしたIoU4pxからの違い
4px0.6000位置誤差に非常に敏感
16px0.8824中程度
80px0.9753かなり高い

NMSはスコアの高い候補から選ぶ

推論では、同じ物体の周囲に複数の予測BBoxが残ることがあります。スコア降順に候補を見て、すでに採択したBBoxとのIoUが閾値より高いものを抑制します。クラス別NMSなら異なるクラス間は抑制しません。

for candidate in score_descending: if score < threshold: skip if IoU(candidate, kept same-class) > nms_iou: suppress else: keep

03 / SIMOTA ASSIGNMENT

どの候補に、どのGTを教えるか

YOLOXの現行の公式 yolo_head.py の get_geometry_constraint 型では、各格子の幾何中心をGT中心の周囲へ制限し、候補を減らします。

grid_center_x = (gx + 0.5) × stride grid_center_y = (gy + 0.5) × stride |grid_center_x − GT.cx| < 1.5 × stride |grid_center_y − GT.cy| < 1.5 × stride

全GTについてこの領域の和集合が候補プールです。GTごとに範囲外となる候補には、非常に大きい幾何ペナルティを追加します。つまり「候補になった」ことと「特定のGTに割り当てられる」ことは別です。

p_class_for_cost = sqrt(sigmoid(class_logit) × sigmoid(obj_logit)) classification_cost = BCE(p_class_for_cost, one_hot(GT_class)) を全クラスで合計 pairwise_iou_loss = −ln(IoU + 1e−8) cost = classification_cost + 3 × pairwise_iou_loss + 1e6 × (GT中心範囲外なら1、内なら0)

教師ごとの候補BBoxとGTのIoUを並べ、上位10個までのIoU合計を整数化してKを決めます。各GTはCostが低い順にK個を選択し、1候補が複数GTに選ばれたら最小CostのGTに一本化します。

topK = min(10, 候補数) dynamicK = max(1, int( sum(topK_IoU) )) 選択 = costが小さい順のdynamicK候補 競合 = 同じ候補が複数GTに選ばれたら最小CostのGTを残す

ここでの int は非負値を0方向へ切り捨てるため、IoU合計が3.8ならK=3です。競合解消で最終的なGT別正例数がKより少なくなることもあります。

バージョン差に注意：過去のYOLOXコードには「GT Box内または中心近傍」で候補抽出し、Box内かつ中心近傍を優先する実装もあります。本Unitの実装は2026-11-04に確認した公式mainの get_geometry_constraint と半径1.5に合わせた教育用再現です。再現実験では利用するYOLOXのcommitを固定してください。公式実装を参照。

04 / LOSS & GRADIENTS

正例割当は「答え」を作り、Lossは差を測る

SimOTAで決まった正例BBoxには回帰GT、クラスGTが与えられます。Objectnessは全候補で学習し、正例では1、負例では0です。クラスGTは1-hotをIoU品質で重み付けしたものです。

IoU_Loss = 1 − IoU(pred_box, gt_box)² Obj_Loss = BCEWithLogits(obj_raw, 0 or 1) Cls_Loss = BCEWithLogits(cls_raw, matched_IoU × one_hot_class) L = [ 5 × Σ IoU_Loss(正例) + Σ Obj_Loss(全候補) + Σ Cls_Loss(正例) ] / max(num_fg, 1) ※ L1を有効化すると追加項が入る（ここではoff）

Unit 04のミニ実験では「1正例・1負例」の例を使い、負例obj logitを固定します。公式の一般的な合計式を、計算値まで追跡できるよう簡略化しています。

微分はどこへ伝わるのか

BCEWithLogits(z,t) = softplus(z) − t×z softplus(z) = max(z,0) + ln(1+exp(−|z|)) ∂ BCEWithLogits(z,t) / ∂z = sigmoid(z) − t BBox中心に対する ∂(5×IoU_Loss)/∂dx ≈ [L(dx + ε) − L(dx − ε)] / (2ε)

例えばobj rawが−1.5、正例targetが1なら偏微分は sigmoid(−1.5)−1 ≒ −0.8176 で、勾配降下はこのlogitを増やす方向です。

分類のIoU品質ターゲットは、割当計算中に決めて勾配を止めて使います。そのため「BBoxを変えたら品質ターゲットも変わる」ことと「1回のbackpropでクラスLossからbbox変数へ勾配が流れる」ことは別です。本実験ではBBox偏微分には回帰Lossのみ使っています。

研究の問い：IoU=0の状態では、IoU Lossの局所的な横方向勾配が0になる場合があります。BBoxの表現形式、割当条件、Lossの形、学習初期の予測分布が、極小物体でどのように相互作用するかを観察してみてください。先にSigned LTRBを正解として紹介することはしません。

05 / TINY OBJECTS

「検出できない」は、どの段階の問題？

小頭部でRecallが低いとき、原因は1つとは限りません。特徴抽出で情報が失われたのか、BBox候補が適切か、正例割当がなされたか、Cost・Loss・勾配が十分か、出力ScoreとNMSで落ちたのかを分ける必要があります。

特にP3（stride=8）では、4pxの頭部が1格子より小さいことが普通です。一方、SimOTAの中心制約は4pxのGTでも候補を確保する場合があります。小さいから必ず正例がゼロになる、と結論してはいけません。 候補供給とBBox品質・classification学習は区別して診断します。

改善策は実験前に断定せず、候補ごとのIoU・score、割当数、Lossと勾配、特定のサイズ層でのAP/Recallを同条件で測ることが重要です。

理解度チェック

Q1. YOLOX DecodeとSimOTA候補中心で「+0.5」が違うのは？

Decodeはrawのtx/tyを整数grid indexに加えます。一方、候補の幾何中心は格子セルの中央を取り、(grid+0.5)×strideです。別用途であり数式を混同できません。

Q2. 4px四方のBBoxを1pxずらした場合、IoUはいくつ？

共通面積3×4=12、和集合4×4+4×4−12=20で、IoU=12/20=0.6です。

Q3. NMSとSimOTAは同じもの？

違います。NMSは推論後の重複予測抑制、SimOTAはGTに対する学習正例割当です。

Q4. `dynamicK=6`のGTが最終的に5個しか持たないことはある？

あります。別GTと同じ候補を選択し、競合を最小Costで解消した結果、最終正例数が少なくなる場合があります。

Q5. BBoxのIoU=0なのに勾配も0になった場合は何を疑う？

IoU Lossの局所勾配、BBoxの重なりの有無、正例割当の状態をまず確認します。初期のraw予測が小BBoxと無関係に離れているなら、IoU Lossだけでは方向がわからない可能性があります。
