モデルデータSimOTALoss推論AP50実験結果課題

1. ネットワークを組み立てる

本章は公式YOLOX-Nanoのネットワーク形状を参考にした独立実装です。設定は depth=0.33、width=0.25、depthwise=True、クラス数1です。ネットワークの総パラメータ数は896,754です。訓練手順は本章向けの簡略版で、公式COCOレシピとは異なります。

入力 (1,3,128,128)
Backbone (Focus → dark2 → dark3/dark4/dark5)
Neck (PAFPN) → P3(64,16,16), P4(128,8,8), P5(256,4,4)
Head (BBox4 + Objectness1 + Classification1)
候補位置 16²+8²+4²=336 個

YOLOXのP3/P4/P5はそれぞれstride=8/16/32です。Tensorの形状（B,C,H,W）を追い、各格子で何を予測するかを説明できるようにします。

2. 教師データを準備する

画像とGTは同じseedを使ってコードで生成します。128×128の暗い背景に、色の付いた長方形が1個だけ存在します。GTは中心と幅高さ (cx,cy,w,h) の4値です。

検証用6枚は学習用画像とは別の乱数列から生成します。少量データのAP50の変動は極めて大きく、未知の写真や実物体への汎化は示しません。

3. どの格子を正例にするのか

Unit 04で解説した中心制約型のSimOTAを、1GTの場合に限定して実装します。GT中心からの距離が各軸で 1.5×stride 未満の候補を集め、BBox IoUと分類のコストを用いて動的に正例を選びます。

candidate_center = (grid_index + 0.5) × stride
cost = −log(√(σ(obj)·σ(cls))) + 3 × (−log(IoU+ε))
dynamic_k = max(1, int(Σ top10 IoU))
positive = argmin(cost, k=dynamic_k)

この例は1画像1GTなので、複数GT間の競合解消は起こりません。完全なSimOTA実装では、複数GTのコスト行列、幾何候補の和集合、重複割当の解消が必要です。

4. Lossから重みの更新まで

候補に対して回帰・Objectness・Classificationの損失を計算し、正例数で正規化します。BBoxはraw値から復元し、IoUを使って損失を計算します。Obj損失にはすべての格子を含みます。正例の分類教師にはstop-gradientしたIoU品質を用います。

L_reg = 5×mean(1−IoU²)
L_obj = sum(BCEWithLogits(obj, target)) / num_positive
L_cls = sum(BCEWithLogits(cls_positive, IoU.detach())) / num_positive
L_total = L_reg + L_obj + L_cls
model.train()
optimizer.zero_grad(set_to_none=True)
raw_maps = model(image)
loss, diagnostics = train_step_loss(raw_maps, gt)
loss.backward()
optimizer.step()

train_step_loss が勾配を保持することが重要です。途中で .item() や .detach() を使ってLoss本体を切り離すと、学習できません。SimOTAの正例選択だけは離散操作として勾配を止めます。

5. 推論時は何が違うか

推論では model.eval() を使い、BBoxをデコードして各格子のScoreを計算し、NMSで重複を抑制します。

bbox_center = (grid_index + raw_xy) × stride
bbox_wh = exp(raw_wh) × stride
score = σ(objectness) × σ(classification)

BatchNormは学習モードではミニバッチ統計を使い、推論モードでは移動平均統計を使います。本章のbatch=1 では、この差が非常に大きくなる可能性があります。訓練中の良いIoUが、そのまま推論時の良いBBoxを保証するとは限りません。

6. AP50を数える

評価では各画像の予測をScore順に並べ、IoU≥0.5かつ未検出GTへの最初の一致をTP、重複や不一致をFPとします。PR曲線の面積（連続補間）をAP50とします。TP/FP/FNは別途Score≥0.25で計算しているため、AP50とTP数は一致しないことがあります。

6GTしかないため、TP1件の増減だけでもRecallは1/6（約0.167）刻みになります。学習画像のAP50が上がっても、検証AP50が同じように上がるとは限りません。

7. 再構築後の実測比較

1枚学習では学習モードの正例IoUが高くなった一方、model.eval() で推論したBBoxのIoU・AP50が低い結果となりました。原因をBatchNormだけと断定することはできません。 モデル状態や正例とScoreの対応、評価モードの差を追加診断する必要があります。

前回の作業記録には「1枚学習AP50=1.0、8枚学習検証AP50≈0.7857」が残っています。しかし、その生成器・学習済みチェックポイントは失われているため、現時点で原結果を再現できたとは主張しません。今回の比較は完全に別の実行結果です。
